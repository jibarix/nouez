# Tools

Part of [nouez's documentation](../README.md#documentation).

| Tool | What it does |
|---|---|
| `StartConsultant` | Starts a background consultant in a project directory: Codex when it is installed, otherwise Antigravity (always read-only; never asks for approvals). With neither installed, says so. If a consultant it started already works in that project, returns it and starts nothing unless `new: true`. Never reuses a session you opened yourself. Says so if a newer nouez is out (see [nouez updates](setup.md#nouez-updates)), or if the Codex CLI or daemon is out of date (see [Codex updates](setup.md#codex-updates)). |
| `ListConsultants` | Lists Antigravity consultants and Codex sessions (those loaded on the local daemon, plus `StartConsultant` sessions it has unloaded), one line each: state or verdict, age, kind, project, name, model and effort, id and title. First come finished turns whose reply Claude hasn't fetched (“done, no reply logged”), changes, no or incomplete verdicts logged in the last 24 hours, and turns running for ten minutes. No prompts or replies are shown. With `cwd`, only the sessions in that repo. |
| `SendConsultantMessage` | Sends a message into a session, waits 5 seconds by default, and returns the reply if it is ready by then, or the turn id and a waiter command if not. If the session is idle the message starts a new turn; if a Codex session is busy it steers the running turn (a message this server already delivered to the running turn, as when Claude sends it again after its context was summarised, isn't sent twice: the result gives that turn's id), but only one this server started: a turn typed in Codex itself, or one from before the server restarted, is refused with nothing sent (as is any message to a busy Antigravity consultant). Unloaded Codex sessions are reloaded first. Refuses a session you opened yourself unless `allow_user_session: true`. A new turn on a Codex quota that reports its limit reached and no credits is refused, with nothing sent and where to go instead; a used-up Antigravity group only adds a `(Usage: ...)` note, and a forecast that a window runs out nothing to the result (see [Choosing a consultant](consultants.md#choosing-a-consultant)). |
| `GetConsultantReply` | Reads a reply without sending anything: the latest turn, or a specific turn id. Use it after sending with `wait: 0` or after a timeout. While the turn runs, it shows the output so far. With `offset`, reads a long reply from that character on. |
| `GetConsultantHistory` | Lists a consultant's recent turns, newest first, one line each: turn id, status, when, how long, who sent it, and the first line of the message and of the reply. Reads only. |
| `OpenClaudeSession` | Opens a new terminal window running an interactive Claude Code session with Remote Control in `cwd` (required), named `name` (default: the folder's name), optionally with a first `prompt`, or picking up an earlier conversation held in that folder with `resume` (the id of a conversation in `ListClaudeSessions`' list for the folder; there is no "latest": Claude is told to show you that list first, and nouez checks the id it passes). It starts on Opus (`model`, default `opus`, the latest Opus) at medium effort (`effort`: `low`, `medium`, `high`, `xhigh` or `max`); Claude passes others only when you ask. The session saves its transcript like one you started yourself. `create: true` makes the folder if it doesn't exist, and makes it a project: `git init` there (unless it is inside a git repository already; git's sample hooks left out) and a starter `CLAUDE.md`. Without git it says so and opens anyway. In a folder Claude Code hasn't been trusted in (or trusted only through a folder above it while it has its own `.claude/settings.json`), it opens nothing and gives a report of what the folder's settings would run, unless `trust: true` is given (you saw that report and said you trust the folder: nouez records that, after a backup, for a folder whose report this nouez server gave, which in Claude Code means this conversation; a folder `create: true` makes outside git in the same call has no settings and needs no report) or `open_untrusted: true` (it opens a session that waits at the trust question). In a trusted folder it then checks for up to 30 seconds that the new session is running and connected to Remote Control, and says if another session was already running in that folder. A resumed conversation that doesn't connect may have been refused its old Remote Control session because your account now requires trusted devices (its window says "Trusted devices now required"): typing `/remote-control` in that window starts a new one, and nouez's report says so. |
| `ListClaudeSessions` | Lists the interactive Claude Code sessions registered in your Claude Code config folder: name, process id, folder, status, Remote Control, and which one is the caller. With an absolute `cwd`, also lists saved conversations from that exact folder, newest first (`limit` defaults to 10, maximum 50). Each shows last activity, session id and open status. A conversation is skipped if its folder cannot be verified in the first 256 KiB. For the custom title and git branch it reads the first and last 256 KiB, skipping records over 64 KiB. It shows the last value it finds for each. A title set outside those bounds can be missing or an older title can show. Pass the chosen id to `OpenClaudeSession` as `resume` with the same `cwd`. |
| `ListProjects` | Lists the folders in `folder` (default: the one holding the session's own folder; in the dispatcher, each of its projects folders): git, trust, running sessions and project settings files. Reads only. |
| `OpenStatusScreen` | Shows the status screen (`server.py top`) on the computer, on its `page`: `usage` (the default) or `consultations`, where the user watches every consultant's latest turn. Switches the screen already open, or opens one in a new terminal window when none is. `days` 1, 7, 30 or 0 (all) picks the period counted; a new window starts on 7 without it, and an open one keeps its own. |
| `ArrangeWindows` | Windows only. Arranges the Claude Code session windows `OpenClaudeSession` opened in a grid on one screen, now (never the status screen), and says how many it arranged, left out or couldn't fit. Automatic arranging is off by default. Pass `auto: true` to turn it on, `auto: false` to stop, or omit `auto` to arrange once. Each box needs about 60 by 16 characters. Extra windows stay where they are. See [Arranging nouez's windows](status-screen.md#arranging-nouezs-windows-windows). |
| `CloseClaudeSession` | Closes one of them by `name` (or `pid` when names repeat), keeping its transcript. Never the caller, and on macOS and Linux only a process it confirms is that session. |
| `ConsultantBudget` | Shows the usage left on your Codex subscription and Claude Code's own and, with `agy` installed, Antigravity's quota groups, with reset times and pace; Claude Code's sign-in end; the Codex and Antigravity models and their levels; and Artificial Analysis model scores. With `kind`, only the suggestion and its notes, unless `details` is true; with `revision: true`, the pick for a message that carries the work's diff, never a Claude model. Agy's quota reading is reused for 90 seconds. Reads only; see [Choosing a consultant](consultants.md#choosing-a-consultant). |
| `StopConsultant` | Archives a Codex session that `StartConsultant` started, ending a turn still running first; ends an Antigravity consultant's running turn and forgets it. With `turn_only`, ends only the running turn: the consultant keeps its context and takes the next message. Needs the exact name or full thread id. Refuses sessions you opened yourself. |

`StartConsultant` arguments (all optional):

| Argument | Default | Meaning |
|---|---|---|
| `cwd` | the client's first workspace folder when it shares them, else the folder nouez started in | Absolute path of the project the consultant works in; Claude is told to pass it |
| `model` | your Codex config; Antigravity: `gemini-4-neon` | Model (new sessions only). Without `provider` and without Codex installed, a Codex model name is ignored, and the result says so |
| `title` | | Session title, shown in Codex (new sessions only) |
| `instructions` | | Standing instructions for the consultant's role (new sessions only) |
| `new` | `false` | Start a new session even though a consultant already works in this project |
| `provider` | `codex` if installed, else `antigravity` | `codex`, or `antigravity` for a consultant on the Antigravity CLI (see [Antigravity consultants](consultants.md#antigravity-consultants)). An explicit choice is kept: `codex` without Codex installed is an error |
| `effort` | `high` | Antigravity only: the model level of a new consultant |

`SendConsultantMessage` arguments:

| Argument | Required | Default | Meaning |
|---|---|---|---|
| `to` | yes | | Session name from `ListConsultants` (e.g. `codex-myproject-a1b2c3`), full thread id, or unique id prefix/suffix. `name` is accepted as an alias. |
| `message` | yes, but for `second_opinion_of` | | The text to send |
| `second_opinion_of` | no | | Name the first consultant. Start a fresh consultant on the other provider and omit `message` and `owner_words`. Nouez forwards the original brief and the work it referred to. A consultant that already received a message is refused. See [blind-opinion conditions](rules.md#rule-blind-opinion), including which first rounds and revisions can be forwarded. |
| `from` | no | `Claude Code` | Sender label shown to the consultant |
| `owner_words` | no | | The user's own words, as they typed them. Sent first and marked off, with the rest of the message labelled as the sender's. Claude passes it only when it has the user's words to quote |
| `revision` | no | `false` | Start the message with the git commit, branch and number of uncommitted paths in the consultant's folder, and ask the consultant to name that revision in its answer. With uncommitted changes, also take their diff once, save it under its SHA-256 and point the consultant at it |
| `base` | no | | With `revision: true`, compare the working tree to the merge base of HEAD and this branch, tag or commit id available locally. The revision line names the range even when the working tree is clean |
| `attach_diff` | no | `true` | With `revision`, Antigravity normally sends the saved diff text to Google, including deleted lines and included untracked files. On an ordinary send, `false` leaves the brief and revision line in the message. The consultant can still read project files. Antigravity refuses `false` for a blind opinion on a revision. See [how each provider receives the diff](rules.md#rule-diff-attachment). |
| `model` | no | nouez's pick | Model id, e.g. `gpt-6-astra` (Codex) or `gemini-4-neon` (Antigravity), for this message and later ones. The consultant keeps its context. Omit both `model` and `effort` for [the pick at send](rules.md#rule-send-pick). A running Codex turn that accepts a message keeps its current model and effort. Asking to change either is refused. Wait for a running Antigravity turn to finish. See [which running turns accept a message](rules.md#rule-running-turn). |
| `effort` | no | nouez's pick | Reasoning effort (Codex) or model level (Antigravity), such as `low`, `medium`, `high` or `xhigh`; the levels depend on the model, for this message and later ones; send the usual value again to go back. Refused, with nothing sent, while nouez sees the consultant mid-turn, except on Codex for the level the running turn already has |
| `wait` | no | `5` | How long to wait for the reply: seconds (`0` returns once the message is delivered), or `"done"` to wait until the turn ends. Capped at 4 hours |
| `allow_user_session` | no | `false` | Allow sending to a session you opened yourself. Claude sets it only when you ask. With `NOUEZ_ASK_USER_SESSION=1`, you also approve each message in Claude Code's own prompt; with `NOUEZ_NO_USER_SESSIONS=1`, it is refused |
| `kind` | yes | | What the consultation is for: `quick-check`, `re-check`, `review`, `bug-hunt`, `plan-critique`, `research`, `draft` (code as text you check and apply), `fact-check` or `other` when none fits. Kept in the [usage log](status-screen.md#usage-log-and-status-screen). Reviews, re-checks, bug hunts, plan critiques and sends with `revision: true` require a model outside the Claude family. An explicit Claude `model` is refused. See [how nouez picks an independent reviewer](rules.md#rule-independent-review). Reviews and re-checks are counted in rounds (see below). Missing or anything else is refused, with nothing sent |
| `reason` | no | | A short sentence on why this model and effort, for the usage log (cut at 300 characters) |

`GetConsultantReply` takes `to`, an optional `turn_id` (default: the latest turn; for Codex, looked up among the 100 most recent turns; for Antigravity, any turn whose file is still kept), an optional `wait` like `SendConsultantMessage`'s, but defaulting to `0`, which returns at once if the turn is still running, and an optional `offset`: a character position in a finished reply to read from. A reply read with `offset` comes back in pieces of up to 60,000 characters, each ending with the offset to read on from.

`GetConsultantHistory` takes `to` and an optional `limit` (default 20, up to 100). The sender is the `from` label of a message sent through nouez, or "someone typing in Codex" for one typed in Codex itself (`codex resume`). A turn with no message isn't anyone's: when a Codex daemon restart (an automatic update, say) cuts a turn off, the restarted daemon carries it on in a new turn with no message, listed as "Codex carrying on the work of turn …, with no new message".

Most replies take longer than the default 5 seconds. Claude is told not to wait for them. Instead the result gives a waiter command, `python server.py wait <thread_id> <turn_id>` with full paths, which Claude runs as a background command (the Bash or PowerShell tool with `run_in_background`). A path is quoted only when it needs it: in double quotes if it has spaces, in single quotes if it has a character a shell would expand (`$`, a backtick). Such a command runs as is in Bash and in PowerShell after `& `. A path with a single quote needs each shell's own escape, so the result then gives a PowerShell form too, and `allow-rule` prints a rule for each. The waiter checks the turn every 1.5 seconds; when the turn ends it prints the reply (cut at 20,000 characters, with the rest saved to a file) and exits, and Claude Code wakes Claude with that output. Claude Code stops a background command after 30 minutes by default, so after 25 minutes the waiter exits on its own with the output so far and the same command to run again, and Claude starts a new one. If nouez sees no change in the turn for 10 minutes (Codex's session file and agy's event file grow every minute or so while a turn works), the waiter exits early instead, saying the consultant may be stuck, with the same command to keep waiting; Claude tells you, so a stuck turn costs 10 minutes rather than 25. A single command that runs quietly for 10 minutes looks the same. It rides out up to three failed connections in a row, such as a daemon restart. A restart interrupts the running turn and Codex carries it on in a new one; the waiter, `GetConsultantReply` and a waiting send follow it there, and the waiter says so with the reply, naming the daemon's old and new version if it changed. nouez offers the waiter to Claude Code (the client that calls itself `claude-code` when it connects) and to a client that doesn't say what it is. Another client is told instead to read the reply later by calling `GetConsultantReply` with the returned `turn_id`, which returns at once, and so is Claude in a client that can't run background commands. If you would rather have Claude wait, ask it to; it then passes `wait: "done"`, and the call returns when the turn ends (checked every 1.5 seconds), on an error, or after 4 hours. Claude Code keeps such a call in the foreground for about two minutes before moving it to the background. A "still working" result is never a reply. It shows the turn's output so far (the latest 4,000 characters written since the last message reached it), labelled as a snapshot that may change.

While a call waits, nouez sends MCP progress notifications (`notifications/progress`, at most one every 10 seconds) naming the turn, the time so far and the latest line of output, when the client asked for them with a progress token. Claude Code 2.1.295 asks but doesn't display them.

If waiting fails after a message was delivered, the error starts with `Delivered to`, so Claude knows not to send it again. When the waiter gives up on its connections, it says the wait ended, not the consultant's turn, which may still be running.

If a third review round still asks for changes, Claude shows you the open points and you decide whether to continue. Set `NOUEZ_REVIEW_ROUNDS_STOP=1` to refuse a fourth round. See [which reviews count as the same work](rules.md#rule-review-rounds). The chain in `review-rounds/` also holds the first brief for `second_opinion_of`.

Replies longer than 60,000 characters are cut there. The full text is saved to `nouez/replies/reply-<turn id>.md` in your cache folder (deleted after 14 days: nouez checks when it starts and each time it saves another), and the cut reply ends with that path and the `GetConsultantReply` offset to read the rest.

When `StartConsultant` reuses a consultant, its result says when the consultant started, how many turns it has had, and what its last turn was, so Claude can tell whether it is still the right one or a fresh one is wanted. `SendConsultantMessage` says which model and effort the consultant runs on. A turn that failed inside Codex (a dropped connection, for example) is reported as such: sending the message again is safe, since the consultant keeps its context.

`StopConsultant` takes `to` and an optional `turn_only` (default `false`). `StopConsultant` doesn't accept an id prefix or suffix, so a typo can't stop the wrong session. `ListConsultants` takes an optional `cwd` to list only the sessions whose working directory is in that path's git repo (outside a repo: under the Claude Code workspace folder that contains the path, or under the path itself), and an optional `include_all` (default `false`, ignored with `cwd`) to also show Codex-internal threads such as subagents.

`wait` replaced `until_done`, `timeout_seconds` and the boolean `wait` in 0.4.0; the old arguments get an error that names the new form, and nothing is sent.

Boolean arguments take `true`/`false` (or the strings `"true"`/`"false"`); any other value is an error rather than a guess.
