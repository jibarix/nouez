# Limitations

Part of [nouez's documentation](../README.md#documentation).

- Local only: it talks to the Codex daemon and runs `agy` on the same machine, and opens and closes Claude Code sessions on the same machine.
- `ListClaudeSessions` reads `~/.claude/sessions` (under `CLAUDE_CONFIG_DIR` if you set it), which Claude Code keeps but doesn't document. A Claude Code update could change it. On Windows a session is listed only if its entry records when its process started, so an entry can't point at an unrelated process that reused the pid.
- Closing a session's window is Windows-only. Elsewhere closing a session ends its `claude` process; its window closes only if the terminal closes when its command ends.
- On macOS, the first `OpenClaudeSession` or `OpenStatusScreen` window makes macOS ask whether the app Claude Code runs in may control Terminal. Allow it, or nothing opens (System Settings → Privacy & Security → Automation changes it later).
- Telling the caller's own session apart is thorough only on Windows, where nouez walks the whole chain of parent processes. Elsewhere it walks the chain with `ps`, and refuses any session it runs under; if `ps` can't be run, it knows only its immediate parent.
- With "require trusted devices" on for your Claude account, a conversation reopened with `resume` can come up without Remote Control: its old Remote Control session was made before the requirement. Typing `/remote-control` in its window on the computer starts a new one; it can't be done from the phone.
- Nothing can start a session on the computer from your phone unless something there is already running and connected: the [dispatcher](phone.md#the-phone-dispatcher), or an open Claude Code session with Remote Control. The dispatcher starts at your sign-in, not at boot, so a computer that is off, asleep or at the sign-in screen is out of reach, and renewing Claude Code's sign-in needs the computer.
- The dispatcher's sign-in start was tested live on Windows only; the macOS launch agent and the Linux autostart entry are covered by unit tests. It tells it is connected from what `claude remote-control` prints, which Claude Code doesn't document, so a Claude Code update could change it: the dispatcher would still run, but its status would read "not connected", and each `claude` would be ended 5 minutes after it starts and started again after the restart wait (30 seconds, doubling up to 15 minutes).
- The trust check reads git's files, not Claude Code's code. For a worktree whose git data was moved out with `--separate-git-dir`, it says it can't tell, except when that git folder is named `.git` and sits beside other files: then nouez, like `git worktree list`, takes that folder for the main checkout.
- `ConsultantBudget`'s suggestion gives model ids ready to pass, but its score list (`details: true`) names models as Artificial Analysis does ("GPT-6.2 Sol (high)"); matching those to model ids is left to Claude. Artificial Analysis scores API access at set effort levels, which may differ from a subscription's.
- `server.py top` counts tokens from Claude Code's transcripts and Codex's session files, which neither documents; an update to either could change them. Output tokens only: a reply's input and cached tokens aren't counted.
- `server.py top` runs the screen under a small process that restarts it on an update. That process keeps its own version until you close the window. A file changed again just as the screen restarts runs unchecked; if it fails, the window waits for the next update.
- Closing the panes of earlier versions at a server's start works on Windows and Linux only. macOS has no handle that keeps a process id from passing to another program between the check and the signal, so there nouez leaves those panes open: close them yourself. On Windows a pane whose `codex` has exited is left open if anything else runs in its window, even a command that ended a moment before the check.
- If you stop an Antigravity consultant and the nouez server quits in the middle of the stop, a turn whose agy later fails on its own can read as stopped rather than failed.
- An Antigravity consultant can't be kept from agy's `schedule` tool: agy has no deny rule or setting for it. Scheduling changes no files, but it can keep a turn waiting until the 30-minute limit. nouez tells the model not to schedule anything, and the waiter says a turn may be stuck after 10 minutes without a new event. agy's `-p` mode and its event stream aren't documented as stable; an agy update could change them.
- Elsewhere than Windows, only the nouez server that started an Antigravity turn can tell its process is still agy, so after a reconnect, or from another session, `StopConsultant` won't end it; it ends at agy's 30-minute limit. There, too, that server keeps its turns' processes by process id alone, and a status check can reap an ended one just as a stop signals it; the time between is very short, and the stop signals only processes it started. On Windows nouez's cache folder isn't made private by nouez: it relies on `%LOCALAPPDATA%` being yours alone, as it is by default.
- If nouez can neither save a new Antigravity turn's process id nor end that process (a full disk, say), it says so and asks you to end agy in Task Manager. Until you do, that agy runs unseen: after 30 seconds the turn counts as failed, so another message can start a second turn beside it.
- Arranging windows is Windows-only, and works only with Windows Terminal: nouez opens its windows in Windows Terminal whenever `wt.exe` is installed, whatever the default terminal is; without it they open in a console window and aren't arranged. It finds each window through the console that Windows Terminal hosts for its tab, which neither Microsoft nor Windows Terminal documents for this; an update could change it. Automatic arranging is off by default. The grid uses one screen, and each box needs about 60 by 16 characters, so a 1920 by 1200 laptop screen at 150% scaling fits four; extra windows stay where they are. A window that won't take its box (a Windows Terminal run as administrator, which nouez can't move, or one that has stopped responding) is asked three times, then left where it is. A window whose command has ended but that Windows Terminal keeps open (its `closeOnExit` setting) leaves the grid. At most 62 helpers are watched for their end at once; others are noticed when their window closes or moves.
- A consultant the Codex daemon has unloaded is found in Codex's own index of sessions, among its 2,000 newest not archived. A Codex whose index can't say which client started each session is checked only in its 50 most recent sessions. Older ones can still be reached by their full thread id.
- Uses the experimental Codex app-server protocol (`thread/start`, `thread/resume`, `thread/list`, `thread/loaded/list`, `thread/read`, `thread/name/set`, `thread/turns/list`, `thread/archive`, `turn/start`, `turn/steer`, `account/rateLimits/read`, `model/list`), which may change between Codex releases. See [Tested with](../README.md#tested-with).
