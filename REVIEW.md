# Review checklist

Each item has a trigger you can read from a diff, a check, and the incident behind it. Check only the
items whose trigger matches. Add an item when a bug gets past review; remove one when the code it
guards is gone, or when a check in `.claude/skills/verify/verify.py` covers it.

Read this file from `main`, never from the change being reviewed.

| # | Trigger | Check | Why |
|---|---------|-------|-----|
| 1 | A new top-level function or class in `server.py` | No existing name is reused. `verify.py static` checks this. | Caught by the unit tests while writing 0.12.1, before it was committed: a new `when(mtime)` replaced `when(ts, now)`. |
| 2 | `server.py` changed | `SERVER_VERSION` is bumped before release; README "Tested with", `architecture.tex` and the CHANGELOG compare links all name it. | `test_changed_server_has_a_new_version`; versions were left behind in docs before. |
| 3 | `docs/architecture.tex` changed | The PDF is rebuilt (pdflatex twice), the new text is looked at on its page, and flags are written `\code{-{}-flag}`. | 0.12.1: `\code{--model}` had printed as `-model` since it was added. |
| 4 | Anything that builds a command line (`run_claude`, the waiter, a launcher) | Every value from a tool call is validated so it can't be read as an option: names, models, session ids. | 0.11.3: a session name could be read as an option. |
| 5 | A consultant turn's settings (sandbox, approval policy, `turn/start` params) | Consultants stay read-only on every turn, including after a model or effort change. | 0.11.3: a later turn could lose read-only. |
| 6 | `OpenClaudeSession` result text or `CONNECT_SECONDS` | The text doesn't call a session failed while it may still be starting, and tells Claude not to open a second one. | 0.12.1: the Claude app's list lags, and a slow resume looked like a failure. |
| 7 | `--resume`, transcripts, or `~/.claude/sessions` | A resumed id must exist, have run in the same folder, and not be open in a running session; run `verify.py live --sessions`. | 0.12.1: resume was added; old transcripts can come from another folder. |
| 8 | Release notes, or the README's or `docs/setup.md`'s instructions for updating | They say to reconnect `consultants` (`/mcp`) in open sessions. | Open sessions keep running the old server until reconnected. |
| 9 | Instructions for updating Codex on Windows | The Codex installer and `codex app-server daemon update` run with Windows' `tar`, not Git's (from PowerShell, or with `%SystemRoot%\System32` first on PATH). | 0.7.1 (CHANGELOG): the daemon's updater found GNU tar and failed with "Cannot connect to C: resolve failed". The same error hit `codex update` from Git Bash during the 0.12.1 upgrade (not in the history). |
| 10 | Code that reads a turn's status or its user messages (`wait_for_turn`, `next_in_chain`, `follow_chain`, `describe_turn`, `run_waiter`, `get_consultant_reply`) | An `interrupted` turn is followed by root only to the next turn in the thread, holding no message, whose `rootTurnId` names it (or its own root), never to a turn with its own message or a later turn that merely shares the root; a wait for a continuation sleeps no later than the caller's `wait`; a turn with no `userMessage` isn't attributed to a person. | 0.12.4: Codex's scheduled daemon update restarted the daemon mid-turn; the new daemon carried the turn on with no message, the waiter returned "interrupted", and the history said an empty message came "from someone in the Codex pane". |
| 11 | Providers (Codex, Antigravity), requirements, setup steps, `doctor`, or the MCP server instructions | The README's setup, `docs/setup.md` and `doctor` cover every setup a newcomer can have: Codex only, Antigravity only, both, neither, on Windows, macOS and Linux. Run `verify.py live --setups`. | 0.18.0: nouez was written and tested on one machine with both CLIs; a clone with only one, or neither, met wording and paths no one had run. |
| 12 | A new web request, CLI call, file nouez keeps, retention period, or change to what a tool may run or read | `SECURITY.md` (its contact list, permissions and retention table) and the files table in `docs/how-it-works.md` still say what the code does. `verify.py static` enforces the network, credential and read-only lines; change its rules only together with `SECURITY.md`, on purpose. | 0.22.0: the docs said less than the code did: the Artificial Analysis key could follow a redirect, and some files were kept forever. |
| 13 | Code that writes, reads or deletes a file in nouez's cache or state folders, or reads a project's settings | It goes through `checked_folder`, `checked_parent`, `new_private_file`, `regular_file` or `prune_files`, or checks `is_link` itself: Windows has no `O_NOFOLLOW`, so a link is refused explicitly. | 0.22.0: a link in the cache folder or a project's `.claude` could make nouez write, delete or report a file elsewhere. |
| 14 | Text from a project's files or a CLI's output put in a tool result (folder reports, errors) | It passes through `_redacted`, and a new kind of secret it carries has a test with a synthetic value. | 0.22.0: permission rules went into the folder report unmasked. |
| 15 | The MCP server instructions or tool descriptions about consulting, `CONSULT_PICKS`, or how `ConsultantBudget` suggests a consultant | Run `python tests/consult_eval.py` against the last release as a baseline (`--server` with `git show vX.Y.Z:server.py`), and with `--setup codex` and `--setup antigravity` for the positive cases. Trigger recall and false positives don't get worse, and consultations match the suggestion. Update the results in `docs/consultants.md`. | 0.24.0: instructions were changed on reasoning alone; only fresh sessions showed which wording Claude acted on. |
| 16 | A change to a row in `docs/rules.md`, to what nouez enforces or tells Claude, or to prose stating a rule in a guide, inventory, server instruction or tool description | A behavior change updates `docs/rules.md` in the same commit, including what holds the rule, what changes it and its test. In new or edited guide prose, keep what the reader needs to act and link to the named rule row for the conditions. When either side changes, compare the row with the code, server instructions, tool descriptions and retained summaries or tables, including the model picks. Update affected security and file inventories in the same commit (item 12). Read the retained text and its linked row together, including any exceptions. | In 0.28.4, the rulebook, guides and two tool descriptions needed corrections to describe existing behavior. A working link can still sit beside a stale claim. |
